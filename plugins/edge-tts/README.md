# Edge TTS：红色问答附加包

将 Python 文字转语音工具接入红色问答，支持聊天朗读、多种人声、语速、音调、音量，以及供同包脚本调用的自定义命令。

聊天合成结果交给红色问答原生 `【语音】` 命令返回。Python 子进程只处理请求并返回结果，不直接调用机器人接口发送消息。

## 适用版本与安装方式

本目录按照本仓库红色问答 `v1.0.80` 的附加包约定组织，入口是同目录下的 `app.json` 和 **`script.json`**。这里是仓库内的插件源码目录，不代表已经在官方插件市场上架。

这个版本使用目录式附加包。把插件目录复制到本机，或解压 ZIP 后放入附加包目录；不要把它当成新版 `.red.7z` 导入包。

### 1. 放置插件

将本目录的全部内容复制到：

```text
红色问答运行目录/plus_dir/pkg_dir/你选择的插件名/
```

例如：

```text
C:\RedReply\plus_dir\pkg_dir\语音朗读\
```

`app.json` 和 `script.json` 必须直接位于这个目录中，不能再多套一层 `edge-tts`。插件文件夹名字由你决定，不要命名为 `默认包`。

插件以自身的 `【应用目录】` 为基准读写资源。运行期间不要移动或改名；需要移动时先停止红色问答。

### 2. 准备独立 Python 环境

首次安装需要本机有 **Python 3.10 或更新版本**，建议 Python 3.12。Windows 可以双击 `一键创建环境.bat`，完成后窗口会保留安装结果；也可以在插件目录运行：

```powershell
.\setup_env.cmd
```

安装入口会检查现有环境、Python 启动器及常见安装位置。它只选择本机已有的 Python，不自动下载 Python。指定解释器时可以在 PowerShell 中执行：

```powershell
$env:TTS_PYTHON = 'C:\Python312\python.exe'
.\setup_env.cmd
```

或者直接调用安装脚本：

```powershell
python setup_venv.py
```

也可以明确指定解释器，无需先把 Python 加入 `PATH`：

```powershell
C:\Python312\python.exe setup_venv.py
```

安装脚本在插件目录建立 `.venv` 并安装依赖。框架初始化和群消息处理均不会自动执行 `pip install`。

安装完成后，插件通过固定的相对路径启动 `.venv` 内的 Python；运行时不依赖 `PATH` 中能否找到 `python`。

### 3. 重启并检查

新增附加包后重启红色问答，然后在机器人能够接收消息的会话中发送：

```text
语音状态
```

这里会检查本机解释器和依赖，**不会把“环境就绪”当成已经完成联网合成测试**。再发送：

```text
语音 你好，欢迎使用文字转语音。
```

联网合成会把输入文字发送到在线语音服务，无需用户填写 API Key，也不需要安装 Edge 浏览器。实际语音消息能否发送还取决于适配器和协议端；部分 OneBot 实现需要在协议端安装 FFmpeg。

## 聊天命令

| 命令 | 用途 |
| --- | --- |
| `语音 你好，欢迎回来。` | 使用默认人声朗读 |
| `朗读 你好，欢迎回来。` | 与 `语音` 相同 |
| `语音 云希\|欢迎收听。` | 指定人声 |
| `语音 云希\|+20%\|-5Hz\|0%\|欢迎收听。` | 按顺序指定人声、语速、音调、音量 |
| `语音人声` | 查询人声列表 |
| `语音人声 zh-CN 1` | 按语言查看指定页 |
| `语音人声 all 1` | 分页查看所有语言的人声 |
| `语音样本` | 列出参考页全部 28 个样本及核对时的目录状态 |
| `语音示例 晓涵` | 播放参考页已有的 MP3 样本 |
| `语音试听 晓晓` | 用 Edge 实时合成一段固定试听文字 |
| `语音状态` | 查看本机运行环境与插件状态 |
| `语音帮助` | 查看聊天用法 |

表格中用于分隔参数的字符是普通半角竖线 `|`；发送消息时不需要输入 Markdown 转义符。

参数顺序固定为：

```text
语音 人声|语速|音调|音量|正文
```

例如稍慢、音调略低的男声：

```text
语音 云希|-15%|-5Hz|+0%|这是一段稍慢的游戏解说。
```

人声可以填写快捷别名，也可以填写完整 ID：

```text
语音 zh-CN-XiaoxiaoNeural|你好，这里是文字转语音。
```

| 参数 | 含义 | 示例 |
| --- | --- | --- |
| 人声 | 选择实际合成声音 | `云希`、完整人声 ID |
| 语速 | 相对该人声默认语速的百分比变化 | `+20%`、`-15%`、`0%` |
| 音调 | 相对音调变化，单位 Hz | `+5Hz`、`-5Hz`、`0Hz` |
| 音量 | 相对默认音量的百分比变化 | `+10%`、`-30%`、`0%` |

这些参数是相对变化，不是每分钟字数、绝对频率或绝对音量。音调调整也不等于切换人声。接口没有自定义情绪、任意 SSML、声音克隆等功能。

聊天入口接受整数或带单位的整数，语速范围为 `-99～200`，音调为 `-100～100 Hz`，音量为 `-100～100%`。这些是本插件的输入范围，不代表服务保证所有极端值都能达到预期听感。

## 全量人声与完整 ID

### 查询当前能够使用的声音

插件不把内置快捷别名当作人声白名单。查询与调用以在线服务实际提供的完整人声 ID 为依据，可以按语言查询，也可以通过 `all` 分页查看全部语言。默认是 `all` 第 1 页，**每页 20 个**，页码从 1 开始；语言按照前缀匹配，例如 `zh` 会涵盖相应中文地区项。

```text
语音人声 all 1
语音人声 all 2
语音人声 en-US 1
语音人声 ja-JP 1
```

使用完整 ID 实时试听：

```text
语音试听 zh-CN-XiaoxiaoNeural
```

试听合成的固定文字为“你好，欢迎使用文字转语音。这是一段实时生成的人声试听。”，使用本机配置中的默认语速、音调和音量；它与 `语音 人声|正文` 走同一个 Edge 合成接口。

### 参考页的全部 28 个声音

本包保留[原始声音试听页](https://jangviktor-web.github.io/novel2voice/scripts/voice_samples/index.html)的全部 28 个声音名称、完整 ID 和 MP3 地址，可通过以下方式查看：

| 入口 | 实际行为 |
| --- | --- |
| `语音样本` | 列出全部 28 项，并标注核对时是否出现在 Edge 目录 |
| `语音示例 晓涵` | 将该声音已有的参考 MP3 URL 交给原生 `【语音】` 播放 |
| 双击 `voice_samples.html` | 在浏览器中筛选并播放 28 条样本，音频按需联网加载 |
| `.\tts.cmd --list-reference-voices` | 在命令行列出静态参考目录及音频 URL |
| `.\tts.cmd --list-reference-voices --json` | 输出同一参考目录的 JSON |

`语音示例` 播放的是既有样本，不会把自定义文字发送给另一家合成服务。参考项目的[样本生成脚本](https://github.com/jangviktor-web/novel2voice/blob/4df8583e37268fadd80759bd3c0c0f19e8977e3a/scripts/generate_voice_samples.py)使用第三方 HTTP API，与本包直接调用 `edge-tts` 的路径不同。

**2026-11-13 核对快照：**Edge 实时目录返回 322 个 ID；参考页 28 个声音中有 14 个在该目录、14 个未列出；28 个样本 URL 的 HEAD 请求均返回 HTTP 200。实际合成测试中，晓晓返回了 11,232 字节音频，晓涵返回 `NoAudioReceived`。因此，全部 28 条参考音频可以用于试听，但不能把样本存在等同于全部支持通过当前 Edge 接口朗读自定义文字；当前可用声音以在线查询和实际合成为准。

完整参考数据见 [voice_reference.json](voice_reference.json)，其中 `source_page`、`source_repo_commit`、`retrieved_at` 记录了来源及核对时间，每个声音的 `edge_listed_at_check` 保存当时的目录状态。它是一次核对记录，不会随在线目录自动改写。

## 在同包 RedLang 脚本中调用

初始化脚本提供以下三个调用入口，并定义 `EdgeTTS展示` 统一处理结果。自定义命令位于当前附加包内，不会覆盖红色问答内置 `【TTS】`，也不能假定其他包会自动获得这些命令。

| 自定义命令 | 参数 | 返回结果 |
| --- | --- | --- |
| `EdgeTTS请求` | 请求对象 | 解析后的结果对象 |
| `EdgeTTS` | 文本、音色、语速、音调、音量 | 解析后的合成结果对象 |
| `EdgeTTS语音` | 文本、音色、语速、音调、音量 | 原生语音消息内容；失败时为明文错误 |

直接返回语音的示例：

```text
【EdgeTTS语音@你好，欢迎回来。@晓晓@+0%@+0Hz@+0%】
```

取得结果对象供后续处理：

```text
【定义变量@结果@【EdgeTTS@你好，欢迎回来。@云希@-15%@-5Hz@+0%】】
```

`EdgeTTS` 的结果不是可直接传给 `【语音】` 的音频字节集。成功结果中的 `audio_base64` 需要先经过 `【BASE64解码】`，再交给 `【语音】`。通常直接使用 `EdgeTTS语音` 即可，它负责检查错误并完成转换。

原生 `【TTS】` 的返回值是音频字节集；本包的 `EdgeTTS` 返回结构化对象，两者的调用结果不要混用。

动态文字应该作为变量或对象字段传入，不要把未经转义的外部文字拼接成 RedLang 源代码。

低层请求对象可以用于查询，例如：

```text
【定义变量@结果@【EdgeTTS请求@【对象@action@voices@locale@all@page@1】】】
```

合成请求的 JSON 结构如下，空缺的人声及参数使用本机默认配置：

```json
{
  "action": "synthesize",
  "text": "你好，欢迎回来。",
  "voice": "zh-CN-XiaoxiaoNeural",
  "rate": "+0%",
  "pitch": "+0Hz",
  "volume": "+0%"
}
```

音频结果包含 `ok`、`kind: "audio"`、`audio_base64` 和实际 `voice`；列表、状态等文字结果使用 `kind: "text"` 和 `text`；既有样本使用 `kind: "sample"`、`sample_url` 和 `voice`。失败结果包含 `ok: false` 与 `error`。不要在未检查成功标记时直接读取音频字段。

`EdgeTTS请求` 的 `action` 可使用 `synthesize`、`chat`、`voices`、`samples`、`sample`、`preview`、`status` 或 `help`。其中 `sample`、`preview` 的人声放在 `text` 字段，与对应聊天命令的参数一致。

## 本机配置

没有 `config.json` 时直接使用内置默认值。需要调整时，将 `config.example.json` 复制为同目录的 `config.json`，使用 UTF-8 保存：

```json
{
  "voice": "晓晓",
  "rate": 0,
  "pitch": 0,
  "volume": 0,
  "timeout": 12,
  "retries": 1,
  "max_chars": 1000,
  "max_concurrent": 2
}
```

| 字段 | 默认值 | 范围或用途 |
| --- | --- | --- |
| `voice` | `晓晓` | 默认人声别名或完整 ID |
| `rate` | `0` | 默认相对语速，`-99～200` |
| `pitch` | `0` | 默认相对音调，`-100～100 Hz` |
| `volume` | `0` | 默认相对音量，`-100～100%` |
| `timeout` | `12` | CLI 子进程的总时限，`2～60` 秒，包含其内部重试 |
| `retries` | `1` | 网络失败后的额外重试次数，`0～2`；仍受总时限约束 |
| `max_chars` | `1000` | 单条正文最大字符数，`1～1200`；同时受请求字节上限约束 |
| `max_concurrent` | `2` | 合成和人声查询共用的并发上限，`1～8` |

配置在每次请求时读取。未知配置项、错误类型或越界值会报错，不会被悄悄忽略。并发名额已满时直接返回忙碌提示，不建立长期等待队列。

聊天入口默认直连，不读取环境变量中的代理配置，也没有允许聊天用户设置代理的参数。CLI 和依赖安装脚本可以在本机通过 `--proxy` 显式配置代理；系统级 VPN、TUN 或路由仍由系统控制。

## 请求边界与运行方式

- `【命令行】` 的工作目录就是本包 `script.json` 所在目录。启动命令使用固定 ASCII 相对路径，不把文案、人声或用户提供的路径直接拼接进 shell。
- RedLang 将请求对象序列化为 JSON，再以 UTF-8 编码并转换为 Base64，作为一个参数交给 Python。
- 单次请求 JSON 的 UTF-8 内容限制为 **5000 字节**，不是 5000 个汉字。限制包含 JSON 字段及参数，用于给 Windows `cmd` 的命令长度保留空间；正文过长时请分段，或使用 CLI 文件模式。
- Python 标准输出使用 `ensure_ascii` JSON，避免 Windows 命令行输出按 GBK 解释时损坏中文。音频通过 `audio_base64` 交回框架，不通过标准输出直接写二进制。
- 每次请求使用独立临时目录，音频不会使用共享的固定文件名。跨进程锁限制同时进行的请求，默认并发上限为 **2**。
- 聊天请求的 CLI 子进程默认总时限为 **12 秒**，防止单条事件长期占用框架。可通过本机 `config.json` 在允许范围内调整。
- 聊天合成输出上限为 **8 MiB**；超过时返回错误，不继续把音频扩张为 Base64。
- 运行配置属于本机配置，不接受聊天用户随消息任意改写。

在线服务故障、限流、网络延迟或人声变化都可能导致失败。聊天接口适合短文；长文、整篇文件或批量任务使用下面的 CLI。

## 保留完整 CLI 功能

`tts_cli.py` 可以独立使用，保留文字、文件、标准输入、批量转换、SRT 字幕、格式转换及网络参数。聊天入口只返回 MP3，不会将 FFmpeg 转码和长批量作业放入消息处理流程。

在插件目录中使用已安装的独立环境：

```powershell
.\tts.cmd --help
```

`tts.cmd` 自动调用本包 `.venv`；也可以使用 `.\.venv\Scripts\python.exe tts_cli.py`，Linux 使用 `./.venv/bin/python tts_cli.py`。

生成 MP3：

```powershell
.\.venv\Scripts\python.exe tts_cli.py -t "你好，欢迎使用。" -v 云希 --rate=-15 --pitch=-5 -o hello.mp3
```

文件朗读并生成字幕：

```powershell
.\.venv\Scripts\python.exe tts_cli.py -f "文案.txt" -v 晓晓 -o speech.mp3 --srt
```

每个非空行生成一条音频：

```powershell
.\.venv\Scripts\python.exe tts_cli.py --batch "文案.txt" --out-dir output --srt
```

转换为 WAV：

```powershell
.\.venv\Scripts\python.exe tts_cli.py -f "文案.txt" -o speech.wav --ffmpeg "C:\Tools\ffmpeg\bin\ffmpeg.exe"
```

CLI 默认不覆盖已有输出文件，需要覆盖时加 `--overwrite`。负数参数推荐使用等号，例如 `--rate=-15`、`--pitch=-5`。

原始服务音频为 24 kHz、48 kbps、单声道 MP3。WAV、FLAC、OGG 或自定义采样率、声道、码率由 FFmpeg 后处理；提高码率、采样率或转成无损格式不会增加源 MP3 中已经没有的音频信息。

## 与原版 TTS 和本仓库插件约定的关系

| 项目 | 本仓库内置 `【TTS】` | 本附加包 |
| --- | --- | --- |
| 调用参数 | 文本、音色 | 文本、人声、语速、音调、音量 |
| 默认人声 | `YunyangNeural`，云扬 | `zh-CN-XiaoxiaoNeural`，晓晓，可由本机配置修改 |
| 人声选择 | 按音色字符串匹配服务返回的名称 | 完整 ID、中文别名；查询全部在线声音 |
| 返回值 | 音频字节集 | `EdgeTTS` 返回结果对象；`EdgeTTS语音` 将成功结果交给原生 `【语音】` |
| 代理 | 读取框架的代理设置 | 聊天合成默认直连，不继承框架代理设置；CLI 可显式指定 |
| 运行环境 | 框架内置 Rust 实现 | 本包独立 `.venv`，固定相对路径启动 Python |

内置行为依据 [TTS 源码](../../src/redlang/exfun.rs)。本包保持独立命令名称，符合[插件模型](../../docs/idea/README.md)和[附加包约定](../../docs/detailref/README.md)：包名由最终用户决定；资源相对于应用目录定位；初始化只定义命令，不自动安装依赖；消息处理使用有时间上限的短进程；合成结果由框架处理回复，不在 Python 中另行发送消息。

## 更新、迁移与排错

更新时先停止红色问答，再替换插件源码，并按需要重新运行 `setup_env.cmd` 检查环境。安装程序会复用健康且依赖清单未变的环境；明确更新依赖使用 `.\setup_env.cmd --upgrade`。保留本机配置前先检查新版本是否兼容。

不要把正在使用的 `.venv` 当成跨机器或跨 Python 版本的可移植环境。目录移动或环境损坏时，将旧 `.venv` 改名保留，再重新建立；安装脚本不会自动删除已有目录。

| 现象 | 检查方法 |
| --- | --- |
| 没有响应任何聊天命令 | 确认目录层级正确、`script.json` 就在附加包目录内，新增包后已重启 |
| 提示运行环境未准备 | 在本包目录手动运行 `setup_venv.py`，然后检查 `语音状态` |
| 列表有声音但合成失败 | 检查网络和实际服务响应，尝试短文以及完整人声 ID |
| 请求过长 | 减少正文；5000 字节上限计算的是完整请求 JSON 的 UTF-8 大小 |
| 请求繁忙或超时 | 等待后重试短文；管理员可检查并发和本机超时配置 |
| 已合成但无法发语音 | 检查红色问答适配器、协议端日志和协议端 FFmpeg 支持 |
| CLI 转码失败 | 确认 FFmpeg 路径正确，编码器可用，输出格式和音频参数兼容 |
